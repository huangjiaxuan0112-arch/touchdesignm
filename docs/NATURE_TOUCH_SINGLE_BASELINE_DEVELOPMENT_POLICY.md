# Nature Touch — 单一基线与后续开发约束

> 文件用途：供 Codex / 其他 AI 在后续修改 Nature Touch 前阅读并遵守。
> 项目原则：**一个当前开发基线、一条正式观众控制路径、一个官方展览启动入口；不自动新增 RC 版本。**
> 本文件是开发约束，不是固件部署许可，也不代替实际硬件验收。

## 1. 当前项目结论

- 用户已确认：Nature Touch 的端到端流程已完成实际测试，WIND、WAVE、BUBBLE 三张卡片都能各自完整完成一轮。**后续不要默认把项目视为尚未跑通，也不要无理由重复完整 E2E。** 若需要引用具体测试次数、硬件结果或已安装版本，仍以对应日志/Manifest 为准，不得编造。
- R1–R5 架构精简及技术债清理已经完成，保留 **Single Orchestrator + Independent Local States**：Electron Main 负责整轮协调；Projector 负责本地媒体；Arduino 负责本地动作与安全状态；iPad 只发送用户意图并订阅状态。
- 已保存的重构源码基线：`aca535f253653fa8da84d92a5b7016efcb1188e7`（`codex/nature-touch-final-baseline`）。**此提交是历史基线，不保证等于此刻工作区 HEAD 或已运行的二进制。** AI 开始操作时需读取实际 Git 状态与启动路径。
- 既有官方展览发布版本为 **RC5**，其 Launcher、Manifest、正式 Bundle/HEX 与 RC4 回退资源应按现有记录保留。重构源码、开发构建、已封存 RC5 包可能是不同产物；不可混装 Main / Preload / Renderer 或凭目录名推断一致。

## 2. 版本与启动规则（必须遵守）

1. **不主动创建 RC6、RC7、新 RC 名称、新平行正式发布包或额外的“最终版”目录。** 不因为更改 UI、时间常量、影片或修复 Bug 就建立新 RC。
2. **日常只维护一个正在推进的开发源码基线。** 在实际当前源码上进行小范围、可追踪修改；Git 提交可以用于历史记录和回退，**Git Commit 不等于新增 RC**。
3. **正式展览只使用已确认的唯一官方启动入口**：项目内 `启动真实展览.cmd` 所指向的受 Manifest/身份门禁保护的 RC5 路径。开发调试使用当前项目已有的开发命令（如 `desktop` 内 `npm run dev`），启动前确认它指向的模式、构建及设备权限；不要另造启动器。
4. 允许为风险隔离使用临时 Git worktree，但这**不构成新的正式版本或第二条部署路线**。完成后受控整合回唯一开发基线，不长期维护平行主线。
5. **未经用户明确要求，不重新构建、覆盖、重命名或修改已封存的 RC5 Bundle/Manifest/HEX、RC4 回退资产，也不自动发布。** 若未来需要把新源码变成可部署版本，应先证明源码可重现构建、身份匹配和可回退，再由用户决定正式发布方式；不得直接改编译产物内的版本字符串冒充新构建。
6. 当现有开发代码与 RC5 封存版本不一致，先说明差异和实际运行入口；不要通过新增 RC 或放宽固件身份校验来“解决”差异。

## 3. 固定的架构边界

```text
iPad / Main Renderer → Electron Main
                    → ExhibitionLifecycleController
                    → ExperienceCoordinator
                    → Mock / Firmware Device Adapter
                              → Arduino（独立本地调度）

Projector ← Main 展览快照；本地预载/播放/结束/错误 → 回报 Main
```

- 正式观众命令入口：`experience:dispatch`；不能恢复已清除的旧 `experience:select/start/stop`、固件直控或第二条执行路径。
- Main 仍是整轮会话和准入的唯一权威；Projector 与 Arduino 各自保留真实、必要的局部状态。不要再建立新的 Controller、状态机或事件总线。
- 保留 operationId / requestId、媒体准备及完成门禁、设备完成确认、单飞串口请求、STOP/FAULT/HOST_TIMEOUT、重复 START 拒绝、断连不自动重启、显式恢复与身份检查。
- 独立 Bench/CLI 是维护工具，不应成为观众的另一条控制入口，也不能假称与 Main 拥有跨进程共享锁。

## 4. 当前时间线与下一项候选需求

**当前已验证的标称软件规则（改动前）：**

| 阶段 | 时间区间（自 START ACK 起） | 时长 |
| --- | --- | --- |
| INFLATE / iPad Preparing / Projector前段 | 0–5s | 5s |
| EXPERIENCE / Projector后段 | 5–20s | 15s |
| DEFLATE / Projector Standby | 20–25s | 5s |
| 完成确认后的 REST / Cooldown | 约25–28s | 3s |
| 最早 READY | 约28s（仅正常且确认及时的情况） | — |

Projector 当前使用连续 **20秒** 静音影片；设备标称动作总时长 **25秒**。实际完成/READY 由设备与媒体的确认门禁决定，不由数字直接放行。

**用户下一项待设计/验证的候选（尚未视为已部署或通过实体测试）：**

| 阶段 | 候选时间区间 | 时长 |
| --- | --- | --- |
| INFLATE / iPad Preparing / Projector前段 | 0–10s | 10s |
| EXPERIENCE / Projector后段 | 10–25s | 15s（不改变内部原节奏） |
| DEFLATE / Projector Standby | 25–30s | 5s |
| 完成确认后的 REST / Cooldown | 约30–33s | 3s |
| 最早 READY | 约33s（以完成与停止确认为前提） | — |

- 候选变更是**前段预充气从5秒增加到10秒**；理论上 iPad Preparing 也增加5秒，Projector 需要与之匹配的**25秒影片**，Arduino 的标称动作总长由25秒变为30秒。不要拉慢后15秒触觉影像来凑时长；媒体素材与 UI 适配由后续专项修改处理。
- **不能直接把10秒预充气写成已批准的实体动作。** 用户观察到原来膨胀高度不足，但延长充气的压力、外壳受力、停泵和残压释放效果仍需独立核实；修改前必须明确限压、允许压力、停止/泄压与相应实测条件。软件模拟通过不是实物批准。
- **时间线调整与架构重构分开。** 不要借调整秒数重新组织 R1–R5，不要因为影片尚未剪好或需要验证就新建 RC。

## 5. 未来 AI 的执行方式

每次接到新任务：

1. 读取本文件、当前 Git HEAD/工作区、启动入口及受影响的源码；只确认**本次修改需要**的事实。
2. 用一句话明确本次范围和“不修改项”，直接在现有开发基线上最小改动；不要再启动全面架构审计、重新梳理 R1–R5 或无故新增阶段。
3. 保持所有未涉及的 UI、影片、固件、协议、动作节奏和安全门禁不变。仅当用户明确指定时才修改相应部分。
4. 运行**与本次改动直接相关的测试**、TypeScript/必要构建。涉及 START/STOP/FAULT、设备身份、媒体同步或时序变更时，必须验证对应边界。不要为一个简单改动机械重复整套历史测试；发布前再统一完整验收。
5. 汇报：修改文件、行为变化、测试 PASS/FAIL/SKIPPED、尚未验证的实物事项。避免把不同构建或历史测试结果混为本轮结果。
6. 未经明确请求，不自动 Commit、Merge、Push、Deploy、访问 COM、上传固件或触发真实执行器。

## 6. 明确不需要再做的事情

- 不再以“还缺新 RC”为由创建平行版本。
- 不再反复做 R0–R5 架构重构或复制旧控制层。
- 不再为媒体剪辑、视觉微调、时间线改动建立新的状态机、Launcher 或设备通信入口。
- 不在每次小修改后都安排100轮稳定性测试或完整发布认证；只有影响到关键链路时做必要针对性回归，最终发布验收单独统一执行。
- 不通过关闭身份门禁、删除 STOP/FAULT 检查、假定设备完成或忽略压力问题来换取“更快跑通”。

## 7. 给 AI 的最终约束（一句话）

**在已经完成端到端测试的 Nature Touch 单一开发基线上继续迭代；保留现有 RC5 官方发布入口和回退证据，不创建新的 RC，不重构既有架构，只针对用户明确提出的具体体验问题做最小、可验证的修改。**
