# D7 RESET 实测更新与最小修复方案

2026-10-29。本次只更新记录并审阅源码／资料，没有访问串口、驱动气泵、上传或修改任何固件。生产固件、原D7输出禁用诊断及LED诊断均保持原样。

## 实测结论保留，RESET 单独失败

[结构化记录](evidence/d7-reset-user-report-20261029.json)保留用户报告原文：1200µs OFF、1800µs ON、1800→1200µs成功关闭；单独移除PWM观察到自动关闭；ON状态下Nano RESET期间气泵继续运行。

前四项按用户提供的真实观察记录通过，不降回模拟结果，也不因RESET失败而否定正常ON/OFF映射。RESET停机记为 **FAIL**。这些不是助手本轮执行的测试，没有伪造命令、回包、示波器或负载电流数据。测试所用确切固件、信号移除方式、失信号关断延迟、RESET按住时间、松开后的状态尚未提供。

此前LED闪烁记录原样保留，不能覆盖这次实际泵运行／停止的报告，也不把本次1800µs实测附会到此前只执行1200µs的串口日志。1200/1800µs映射只适用于已观察的D7，不外推到D5/D6或旧544/2400µs端点。

## 源码已经能确定的内容

| 检查位置 | 结果及意义 |
|---|---|
| `d7_led_only.ino` setup | 只Serial.begin与READY_NO_SIGNAL，不attach、不发送1200µs；复位后不会主动纠正外部开关可能保持的ON |
| 全局状态 | attached=false，pending/applied/activeUs清零；没有EEPROM保存或恢复ON。软件变量清零不代表C93自身复位或负载断电 |
| Servo构造 | 当前库在RAM预存默认1500µs，但构造不启动引脚输出 |
| CONFIRM分支 | 先writeMicroseconds(所选值)，后attach(7)；因此当前源码没有先attach后写入造成默认1500µs输出的启动顺序问题。没有新确认就不应主动发1800µs |
| STOP／超时 | 执行detach、digitalWrite(7, LOW)、pinMode(7, INPUT)，没有发送1200µs。该路径不能替代已测的“1800→1200关断” |
| RESET | 不会先调用STOP或上述结束脉冲序列；MCU硬件复位直接中断执行，程序不能补跑清理代码 |
| 旧d7_start_stop | 始终输出禁用，仅逻辑STOP，不是实体恢复OFF代码 |
| Windows LED工具 | 收到READY清除候选确认和最近应用记录；不会因READY自动发送测试脉冲。其STATUS仅续租，不发1800µs |
| 单次short脚本 | 首次连接在此前用户一次授权下发送SHORT并确认；不会发送LONG，运行中没有恢复ON分支。但运行中再收到READY没有立即判复位故障，需要以后改为立即终止本次试验，不能作为RESET验证工具直接复用 |
| real-actuators.h | 仍锁定；候选OFF是角度0，verified=false，且含全通道初始化，不能只解锁后用于此次D7，也不能把1200µs实测转换成角度0已验证 |

只根据已检查源码，没有发现复位后自动重发1800µs的路径。用户此次测试确切烧录版本未知，因此不能断言实际板上必然运行此源码；若别的固件或外部主机确实重发了ON，必须用那一版本及原始日志另查，不能在此猜定。

## 为什么两类“失信号”可能不同

[ATmega328P数据手册](https://ww1.microchip.com/downloads/en/DeviceDoc/Atmel-7810-Automotive-Microcontrollers-ATmega328P_Datasheet.pdf)说明RESET生效时端口进入高阻。Servo ISR在MCU复位期间不能继续按正常程序发帧；RESET也不等于切断仍连接的USB供电。因此C93可能仍带电，而软件没机会发可靠OFF。

普通移除PWM与RESET必须按实际边界条件比较：

- 手工STOP有显式结束为LOW的动作；RESET没有这一步，可能在脉冲任意位置打断并直接进入高阻。
- 如果所谓移除PWM是拔信号线、保持LOW或停定时器，其电平、偏置及残余连接条件并不相同；目前用户尚未说明具体方式。
- 复位中断时间可能不足以满足开关的失信号判据；或者输入偏置／瞬态／干扰使其未判定为相同的失信号。这些只是待检验假设，不是已确定原因。
- 即使RESET后不再重发ON，没有主动1200µs也可能让外部开关继续原状态。继续运行本身不能证明MCU仍输出1800µs，更不能单凭现象认定C93内部必然永久锁存。

[C93官方页](https://www.rc-factory.eu/prislusenstvi/elektronika/rc-spinac-3-5v-2a)只说明阈值和LED，不规定失信号／RESET安全行为。本次RESET失败已经足以判定：当前组合不能依靠“停PWM就一定停泵”覆盖所有故障。确切原因可留给隔离台架测量S端波形及输出，不能再以真实泵盲试。

## 最小可行修复：待审阅实施，不是当前已部署行为

### 1. 软件只改D7适配层与必要的主机复位处理

保留当前输出禁用版本和统一固件。以后另获授权的D7版本采用以下最小行为，不改展览界面或三模式时间线：

1. 初始化时先预置明确的1200µs，再attach D7，尽早持续发送已验证的OFF；先做OFF初始化，再报告READY、接受命令。禁止先attach后才改脉宽，也不使用1500µs作为过渡。此项是从“启动无信号”改成“启动请求OFF”，需要单独审阅及授权，当前没有修改或上传。
2. 正常STOP、HOST_TIMEOUT、单次时限和故障均写1200µs，并持续保持OFF脉冲，不把detach/LOW当成OFF。设置锁定，任何旧心跳／确认／START不恢复ON，必须重新明确授权和启动。attach失败也不得进入READY可运行状态。
3. 默认ON=false，清所有待执行动作／确认；RESET后不得恢复先前运行。禁止主机自动重发START／LONG；收到新READY、设备时钟回退或连接中断就取消当前试验与排队确认，记为故障。不要用自动重连恢复运行。
4. 日志分开标“OFF已请求”和“用户观察／仪器确认OFF”。OFF生效包含帧传播和开关响应时间，不写一个猜测延时就称为已关断。RESET原因可用于诊断，但不是关断机制。

这能改善应用程序开始执行之后的恢复行为，并复用已测OFF值；不能保证RESET按住期间或bootloader等待阶段的停机。

### 2. 软件覆盖不了的时间段

RESET有效期间、启动等待／bootloader阶段、程序未执行／挂死／供电异常时，setup里的OFF以及同一CPU上的通信watchdog都不能执行。提前到setup第一行，甚至换更早初始化入口，也不能覆盖RESET持续有效的阶段。不能把给同一个Nano加复位watchdog当成外部断能；它还可能再次进入已观察的不安全状态。

### 3. 覆盖RESET继续运行，需要硬件失效断能

若演示要求RESET／控制器失效期间泵也能在明确期限内停下，**必须有独立于该程序的失效断能措施**。保留单USB来源：仅在D7负载供能支路增加适当额定的常态断能许可／开关，控制失效、复位或独立心跳超时即撤销供能；恢复后保持禁止，须新的明确许可。Nano保持供电，D5/D6不修改。

器件／接法由硬件朋友根据已确认接线、电机启动电流、感性保护和回灌路径选定；本记录不猜元件型号、阻值或额外引脚。需验证真实复位、挂起、掉电／恢复条件下的关断时间与不自启。仅增加输入下拉可改善悬空，不能独自证明C93失效关断；新增使能若可能被卡死输出维持，也不算独立保护。切断C93供电必须同时确认不会通过信号线反向供电。

手动拔唯一USB保留为现场应急措施，但不能自动覆盖无人及时操作的RESET事件。断能也不等于卸掉气囊残压，压力限制／卸压条件仍独立保留。

## 本次停止点

正常1200/1800µs控制结果保留。RESET安全未通过；不扩大到D6/D5，不接管真实泵，不上传。下一阶段只需围绕D7完成“软件持续OFF初始化／停止 + 独立失效断能”这两处最小修复，之后再另行安排获批的隔离台架验证；不重写系统。
