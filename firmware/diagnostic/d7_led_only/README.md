# D7 C93 LED-only 独立信号诊断

准备日期：2026-10-29。**仅编译和离线检查完成；未连接串口、未上传、未输出真实信号。**

本版本只供所有真实气动负载已经物理隔离后的 C93 板载 LED 观察。旧 `d7_start_stop`、统一固件、真实驱动骨架、D5/D6 和时间线均不修改。它不是可以连接真实泵使用的 START/STOP 固件。

**后续实测更新（2026-10-29）：** 用户报告D7的1200µs OFF、1800µs ON、1800→1200关断及单独移除PWM关断通过；但ON状态下Nano RESET期间泵继续运行，RESET停机失败。正常ON/OFF数据保留，不外推失信号安全。详见[实测记录](../../../docs/evidence/d7-reset-user-report-20261029.json)与[RESET分析／最小修复方案](../../../docs/d7-reset-analysis-20261029.md)。这不是本LED诊断原有串口日志执行的新增试验，确切实测固件尚未提供。当前源码不变、没有部署修复。

## 脉宽依据与不确定性

[RC Factory C93 官方页](https://www.rc-factory.eu/prislusenstvi/elektronika/rc-spinac-3-5v-2a)给出 >1500µs 导通、<1500µs 断开及 LED 状态指示，但没有完整可接受输入脉宽范围、恰好1500µs行为或失信号保证。

- A / `SHORT_PULSE`：1200µs。
- B / `LONG_PULSE`：1800µs。

两值是跨越厂家阈值、避开544/2400µs旧端点的工程测试选择，**不是厂家已保证支持的输入范围**。本次仅在负载隔离条件下核验模块响应；无响应／异常就停止，不自动扩大范围或扫频。使用已有 Servo 库的约20ms重复帧；5秒期间持续发送所选固定脉宽，不是自动切换试验周期。

即使1200/1800µs的 LED 结果符合规格，也不直接证明旧544/2400µs端点对应的真实负载行为，不宣称原程序矛盾已经完全解决。

## 上传／接 USB 前必须由用户确认

1. 充气泵从供能路径物理断开，不只是断信号或软件停止。
2. 抽气泵及电磁阀也物理隔离，不可能从其他路径得电。
3. C93 控制接线、电平／参考连接、极性及3–5V供电适当，保留单USB架构。
4. 本测试不可能充气；气囊没有待处理残压。
5. 用户在场，可立即拔除USB，且没有其他供能源或回灌路径。

完成上述确认后仍需用户明确授权上传本版本。上传授权不等于授权任意输出；每次脉宽试验另行人工确认。上传、打开串口或USB恢复可能复位 Nano；本草图启动不attach或配置D7，不发控制脉冲，但不保证开关无信号时LED或负载输出处于何种状态。

## 操作协议（以后授权后逐项执行）

9600 baud，ASCII 命令，LF或CRLF结尾。独立身份 `D7LED/1`，不能使用旧模拟版 Windows START/STOP 命令。

| 命令／事件 | 行为 |
|---|---|
| 上电／RESET | `READY_NO_SIGNAL`，D7不配置，无自动试验 |
| `SHORT_PULSE` / `LONG_PULSE` | 只选择脉宽，返回 `AWAIT_CONFIRM pending=编号 requested_us=值`；不输出 |
| `CONFIRM 编号` | 5秒内的匹配编号才会输出一次；编号立即作废，每次需重新选择并人工确认 |
| 活跃期间选择新脉宽 | 拒绝，须先 STOP／试验结束，再选择并确认 |
| `STATUS` | 报告状态，续通信期限；不发起试验 |
| `STOP` | 取消待确认，移除现有脉冲；D7先结束为LOW，再设为无上拉输入；**不是物理OFF命令** |
| 无STATUS达2秒 | 移除信号，取消待确认，旧编号不能恢复输出 |
| 单次输出满5秒 | 同样移除信号，不自动发送另一脉宽，不自动重试 |

计时上限从本次确认应用开始，不含准备时间。日志记录Nano启动后的毫秒、事件、请求及当前脉宽、待确认／已应用编号。所有行固定声明 `physical_off=UNVERIFIED led=UNOBSERVED`，没有伪造传感器反馈。软件上限不等于有硬件独立关断保护。

停止发脉冲、LOW、高阻都不认定为关断；模块可能保持原指示状态。如LED异常、闪烁、模块发热或预期外行为，立即断USB，报告现象，停止继续试验。不得接回真实负载。

## Windows 记录界面

`windows-led.cjs` 复用桌面项目现有 serialport，不安装依赖。不提供上传路径，不自动连接／重连，不自动确认或试验。**仅在隔离确认及上传授权完成后**，按操作人员确认的端口启动：

```text
node firmware/diagnostic/d7_led_only/windows-led.cjs COM数字
```

不带端口运行只显示用法并退出，不接触串口。提供端口才打开串口，可能触发RESET；每500ms发送STATUS，不发送任何试验命令。收到新鲜 `D7LED/1` 状态才接受试验选择／确认。

每次人工输入SHORT_PULSE或LONG_PULSE后查看编号，再单独输入CONFIRM及编号。确认窗口5秒，超时必须重新选择，不会自动重试。未来由助手代发时，需先取得用户对该一次试验的明确确认，再执行对应选择及编号确认；不能预先授权整批循环。

`OBSERVE ON 备注`、`OBSERVE OFF 备注`、`OBSERVE UNKNOWN 备注` 记录人工观察，关联最近一次APPLIED的编号和脉宽。备注须说明观察是在脉冲期间还是移除后；不能用观察录入时间推断硬件切换时间。每次由用户回报，不能由串口响应自动填LED状态。

TX、RX、人工观察、错误和断连按UTC时间追加到 `docs/evidence/d7-led-sessions/*.jsonl`。QUIT／正常退出尽力发送STOP再关闭串口，异常退出依靠软件期限移除信号；两者均不保证开关关断。用户始终保留拔USB能力。

## 编译与离线检查

项目根目录运行 `node test/d7-led-only/verify.mjs`；只编译与虚拟执行，不加载真实串口库，不上传。

本次结果：[验证记录](../../../docs/evidence/d7-led-only-yyFEal/results.json)、[编译日志](../../../docs/evidence/d7-led-only-yyFEal/compile.log)。

- Nano ATmega328P：Flash 5316/30720字节，静态SRAM 354/2048字节。
- 4组实际HEX虚拟执行检查通过：启动与确认门槛；两种脉宽与STOP；2秒失联；5秒单次上限且无重复。
- D7虚拟脉宽误差在请求值±12µs内；无默认1500µs脉冲被观察到；D5/D6输出配置、写入与边沿均无活动。
- 旧诊断、控制器、统一固件及驱动／时间线哈希不变，结果文件有记录。
- Windows工具语法及不带端口的启动退出检查通过；尚未做实体串口验证。

使用已有AVR8js USART RXC兼容适配，干预记录随结果保存。虚拟复位是新CPU执行同一HEX，不包括真实引导程序、电源瞬态、模块或LED。因此不声称已验证真实启动、物理OFF、失信号或掉电安全。
