# Step 3F：D6-only C93 LED诊断（准备阶段）

沿用D7 LED诊断的程序、终端和AVR8js检查，只把目标改为D6与独立身份`D6LED/1`。**未连接串口、未上传、未进行实体测试。** D7诊断、真实驱动、默认模拟固件、Protocol v2及三模式时间表均未修改；不重跑D7测试。

**后续更新（2026-10-29）：** 本版本随后在用户授权下上传，并执行过一次1200µs LED试验，期间与结束后均报告闪烁，拔USB后熄灭，见[原始试验记录](../../../docs/evidence/d6-led-short-SDH3eW/trial.json)。用户另行完成D6实体端点测试，报告旧`inflate()`约2400µs时开关ON且负载侧有电，旧`deflate()`约544µs时开关OFF且负载侧无电，见[独立实测记录](../../../docs/evidence/d6-legacy-endpoints-physical-pass-20261029.json)。保留两份观察，不将后一次测试冒充为本1200/1800µs诊断的串口结果。1200/1800映射、失信号、RESET及气流方向仍未由此报告验证。下文“未测／上传前”属于原准备阶段状态。

## 当前试验边界

- 只能attach D6；D5/D7不配置、不写入。三路真实气动负载必须物理隔离，测试只观察D6开关LED。
- D6的1200µs／1800µs都是待验证的候选值。D7实测通过不代表D6通过；厂商阈值也不等于已知完整输入范围。
- LED响应不证明负载电流为零，不能据此直接解锁D6真实抽气泵控制。
- 先只准备D6；拿到D6现场结果后才准备D5。D5必须分别记录“开关电气导通／关断”和“阀实际气路状态”，不能把LED或线圈通电直接叫作气路打开／关闭。

## 保留的逐次确认与软件限制

| 命令／事件 | 行为 |
|---|---|
| 上电／RESET | 仅READY_NO_SIGNAL，不attach、不自动发脉冲、不恢复旧确认 |
| SHORT_PULSE | 选择1200µs，返回待确认编号，不输出 |
| LONG_PULSE | 选择1800µs，返回待确认编号，不输出 |
| CONFIRM 编号 | 必须在5秒窗口内人工确认匹配编号，才输出一次固定脉宽脉冲列 |
| 运行中再次选择 | 拒绝，须先结束本次试验，禁止自动切换／循环 |
| STATUS | 查询状态并续通信期限，不开始试验 |
| STOP | 取消确认、移除D6脉冲；结束为LOW再转无上拉输入，**不声明物理OFF** |
| 主机失联2秒／单次满5秒 | 移除脉冲、旧确认失效；恢复心跳不会恢复输出 |

9600 baud，LF或CRLF。所有回包均声明`physical_off=UNVERIFIED led=UNOBSERVED`。日志包含请求脉宽、毫秒时间及确认／应用编号。D6失信号、RESET与掉电／恢复行为尚未实测，不能借用D7结果。

## 上传前停止点

当前没有上传授权，也不执行自动端口检测／连接。上传前用户须在断电条件下确认：

1. 抽气泵已从供能路径物理断开。
2. 充气泵、电磁阀同样隔离，任何路径都不能得电。
3. D6 C93控制接线、极性、参考连接及3–5V供电适当，保留单USB来源且无回灌。
4. 测试不会充气／抽气或驱动阀，气囊无待处理残压。
5. 用户在场，可立即拔USB断能。

确认后仍需明确授权上传D6 LED-only版本。上传不包含试验授权；之后一次只请求一个SHORT或LONG脉冲确认，观察后停止并记录。异常立即断USB，不自动换脉宽或重试。

## Windows工具与记录

`windows-led.cjs`直接复用D7版本的交互，匹配D6LED/1身份，拒绝把D7固件当作D6。复用已安装serialport，不改前端、不安装依赖。

仅将来上传获准完成后，才按重新确认的端口启动：

```text
node firmware/diagnostic/d6_led_only/windows-led.cjs COM数字
```

不带端口只显示用法，不打开串口。指定端口会打开串口，可能复位Nano；仅自动STATUS心跳，不自动试验、不自动重连。每次明确选择SHORT_PULSE或LONG_PULSE，再人工输入CONFIRM及匹配编号。

`OBSERVE ON|OFF|UNKNOWN 备注`记录人工观察，注明发生在脉冲期间还是停止后。原始TX/RX、用户观察、错误和断连分别保存到`docs/evidence/d6-led-sessions/*.jsonl`；没有实体观察时不自动填写LED结果。
